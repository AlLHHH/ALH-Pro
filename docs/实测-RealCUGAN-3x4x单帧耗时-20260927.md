# 实测:Real-CUGAN 2x / 3x / 4x 的每帧成本(2026-09-27)

> 补的是待办里那条「Real-CUGAN 3x/4x 实测单帧耗时未补」。**结论比预期好:3x/4x 并不比 2x 贵多少。**

## 一、怎么测的(可复跑)

- 机器:开发机 RTX 4060 Laptop;引擎 `engines\realcugan\realcugan-ncnn-vulkan-2026.exe`。
- 素材:`转头(2).mp4` 抽的 **40 帧 1080p JPG**(`-qscale:v 2`,与视频流水线中间帧同口径)。
- 命令(每档一次冷跑,计时含引擎启动与模型加载;40 帧摊薄后启动开销约 0.05 秒/帧):

```powershell
realcugan-ncnn-vulkan-2026.exe -i in40 -o out -s <2|3|4> -n -1 -m models-se -f jpg -g 0
```

- ⚠ **`-n` 是降噪档位数字**(`-1` 保守 / `0` 不降噪 / `3` 强降噪),**不是模型文件名** —— 传文件名会报
  `invalid outputpath extension type`(这次踩过,记下来免得下次再试错)。`-o` 目录必须**先存在**,否则同样报这个错。

## 二、结果(保守档 `-n -1`,1080p 源)

| 倍率 | 总耗时(40 帧) | 每帧 | 相对 2x |
|---|---|---|---|
| **2x** | 88.3 s | **2.21 秒/帧** | — |
| **3x** | 94.0 s | **2.35 秒/帧** | +6% |
| **4x** | 98.3 s | **2.46 秒/帧** | +11% |

不降噪档(`-n 0`)另用 16 帧粗测过一次,量级相同(2.21 / 1.92 / 2.46 秒/帧 —— 3x 比 2x 还低是这轮
样本太小 + GPU 状态波动造成的噪声,不作数)。

## 三、结论与含义

1. **Real-CUGAN 的成本几乎与倍率无关**:3x 只比 2x 贵约 6%,4x 贵约 11% —— **远不是按输出像素数(2.25×/4×)增长**。
   原因合理:它的计算量主要花在**输入分辨率的特征提取**上,最后那一步上采样占比很小。
2. 因此「3x/4x 会更慢很多」这个直觉**不成立**;选 3x/4x 时的时间和显存代价要与 2x 一样看待(显存另算,输出更大)。
3. **对软件的影响(待办,不紧急)**:`AlhPro.Core\VideoPipeline.cs:122` 的**预计时间兜底表**里 realcugan 只有一个常数
   `1.65`(2x 的历史实测),3x/4x 也会用它 ⇒ 预计时间**略偏乐观约 6~11%**。有两条路:
   - 这台机器**跑过一次自动标定**后,顺序判定与预计时间都吃本机实测,兜底表就不再参与 ⇒ 影响自动消失;
   - 想把兜底也做准,需要把那个常数改成**按倍率分档**(Core 改动 + 补单测)。收益不大,建议与其它 Core 改动一起做。

## 四、诚实边界

1. **绝对值与历史记录不一致**:仓库里记的 1080p 2x 是 **1.61~1.65 秒/帧**,我这次量到 **2.21**(高约三成)。
   两者不是同一时刻、也不保证同一机器状态(本机当时还在跑别的活),输入格式也不同(JPG 目录 vs 当年的口径)。
   ⇒ **本次数据只宜用来比较"倍率之间的关系",不宜当成新的绝对基准**;要绝对值就在空闲机器上按上面的命令重跑一遍。
2. 单机、单次、单素材(动漫、压缩视频帧);真人/其它源未测。
3. 只测了 `-n -1`(默认保守档)的 2x/3x/4x;强降噪 `-n 3` 与不降噪 `-n 0` 未逐档测(同一份网络、不同权重,**预计同量级**)。
4. 显存占用与峰值临时盘未测。
