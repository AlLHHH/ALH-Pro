v1.4.2 2026-09-24 · 四批实测修复:一用就撞上的硬故障 + 一批"不报错但会悄悄做错"的老毛病 + 视频抠图整条下线 + 视频 2x 实测提速 28 倍 + 音频/显卡「白试」落盘

把四批实测修复合在一个版本里:① 一用就撞上的硬故障(Anime4K 在走备用 ffmpeg 的机器上必然失败、「一键参考预估」从来没成功过、开机默认页对不上、音频页三个按钮永远灰、「处理完成」弹窗撞「预览效果」会崩、显存降档重试是空转、三处悬停提示照做会丢任务);② 平时看不见但一直存在的老毛病(音频"显卡不行"记不住账、自定义分辨率入口丢了、补帧可能悄悄少帧、视频可能静默走 CPU 软编);③ 视频抠图整条下线;④ 视频 2x 被静默推到"慢 13 倍"的路已修(实测同一段素材快 28 倍)。全部改动不改变你的画质档位与已存设置。
  • Anime4K 在"合帧走备用 ffmpeg"的机器上必然失败 —— 已修:「1x 修复 · 动漫 Anime4K」把滤镜挂在合帧那一步,而一部分机器(典型是驱动较旧的 N 卡)硬件编码在主 ffmpeg 上探测不过、合帧会自动改用随包的备用 ffmpeg8 —— 那个目录以前没有 shaders 子目录,于是滤镜报 Cannot read file 'shaders/anime4k-v4-a.glsl',整条任务直接失败。 实测:同一条命令在主 ffmpeg 目录下退出码 0、在 ffmpeg8 目录下退出码 -2;现在两个目录都带着色器,ffmpeg8 也返回 0。另外这类失败以前会被报成"硬件编码(nvenc)连续 3 次失败",让人去折腾显卡驱动,现在会明确说是滤镜链的问题。
  • 「一键参考预估」(内容帧率 / 可删比例)从来没成功过 —— 已修:采样命令里的 -vsync 0 在当前随包 ffmpeg 上已被移除,命令必然报 Unrecognized option 'vsync' ⇒ 每次都走降级分支,导入视频后列表项上只挂一个「无法预估」角标。 改成 -fps_mode passthrough 后实测退出码 0,采样产物大小正好(90 帧 × 2304 字节 = 207,360 B)。修完会重新看到"内容≈N fps / 可删 X%"这类预估。
  • 开机默认页对齐(设置里选哪个就是哪个):启动页编号与左侧导航的书写顺序不是同一套,旧代码把前者直接当后者用。实测:设置里选「视频处理」→ 重启进的是当时还锁着的「视频抠图」;选「音频处理」→ 进「视频处理」;选「视频抠图」→ 完全不生效。 「上次退出界面」也有两个错(在音频处理页退出会回到图片放大;在教程或设置页退出会把上次页冲掉)。换算收进 AlhPro.Core.StartupPageMap(带单测):功能页两两互不撞车,非功能页退出不再覆盖记录。
  • 音频处理页的「删除选中 / 清空 / 清除已完成」永远灰 —— 已修:这三个按钮的状态只在"删除 / 清空 / 框选"之后才刷新,加完文件、在列表里点选一条都不刷新(实测同一时刻视频页与图片页是亮的、只有音频页灰)。现在"加完文件"与"选中变化"都会刷新。
  • 「处理完成」还开着时点「预览效果」会抛未处理异常(实测崩溃):WinUI 同一时刻只允许一个对话框,任务跑完弹着「处理完成」时再点「预览效果」,第二个对话框弹不出来会直接抛 0x80000019,用户只看到"点了没反应"。现在弹不出来就降级成状态栏那句话 + 一条日志,不再抛到顶层。 顺带把"被挡回"时的提示改对:以前说"请检查左侧参数…原因见左下角日志"(日志里其实一个字都没有),现在直说"正在处理别的任务,等它结束再点"。
  • 显存不足时的"自动降低分块重试"以前是空转 —— 已修:日志与进度条都在说"分块 auto→512→256→128 逐级降低",但那两条引擎命令的分块参数是写死的 -t 0,降级算出来的值根本没传进去 ⇒ 同一参数白跑 3 次才失败。现在真的按 auto→512→256→128 走。
  • 三处悬停提示说错了(照做会丢任务):视频处理 / 图片放大 / 图片抠图三页的红色「强制结束」原写着"休息时变「跳过休息」,点一下跳过休息继续处理" —— 实际这个按钮从来不会变文案,照提示点下去就是中止整个任务。文案已改成实话,并指明真正的「跳过休息」在窗口底部状态栏右侧。
  • 文案纠偏:"视频批基准 1400 帧/批(实际每批 50~400,按素材长度定)"这句自相矛盾(真实区间是 80~1400),三处已改。
  • 音频分离"显卡不行"这件事记不住账 —— 已修:AI 分离会先把活交给显卡(DirectML),不行再退回 CPU,靠一张"这台卡用不了了"的连击表避免反复白试;但记账用的编号错了 —— 那张表只认显卡(DML)编号,代码却拿引擎编号去记,这两个数在双显卡 / 带核显的机器上不是同一个 ⇒ 账记到别人头上,连击永远攒不够,每首 / 每次任务都要再白试一遍(实测每次白试 2~11 秒)。 现在统一成同一套编号,并且"建显卡会话当场失败"就直接判这台卡在音频上不可用(重启软件会重新试一次),不再等攒够三次。
  • 「自定义分辨率」其实是丢了的 —— 已还原:视频页的「自定义分辨率」面板(填宽 × 高,超分后精确缩放到你要的尺寸)只在倍率选到第 5 项时才显示,而倍率下拉里只有 4 项 ⇒ 面板永远是隐藏的,使用教程那句"选「自定义分辨率」精确指定输出宽高"照着做也找不到。现在倍率是 1x 修复 / 2x / 3x / 4x / 自定义分辨率。 顺带修一处连带 bug(自查时抓到):设置里存的是倍率索引,读回来时旧规则把索引 4 一律当成 2x ⇒ "存得住、读不回"(选了自定义分辨率、保存、重启被静默打回 2x,设置文件里那个 4 会被改写成 1);现在索引 4 照搬,宽高也一起恢复(实测 960×540 重启后仍是自定义分辨率 + 960×540)。
  • 四处"说法过时" —— 已改成实话:降噪开关的悬停提示还在教人"选「自动」时会先给素材体检"(那个档位 2026-09-21 已下线);图片抠图的模型说明写着"本机 GPU 实测最快(0.4 秒/张)",而图片抠图固定用 CPU(GPU 推理会把显卡占满、整机卡);音频页一开工就写"显卡加速",可它只是在尝试显卡(建会话失败就自动改 CPU);批大小报错正文里写死了过时数字(档位已翻倍)。使用教程与官网的同类说法也一起改了。
  • 补帧交付失败会"悄悄少帧" —— 现在会留痕:补帧每段跑完要把引擎产出的帧搬到最终目录,搬运两次都失败时旧代码照样把帧号加一 ⇒ 帧序列里出现空洞(下游按 frame_%06d.jpg 顺序读,撞上"文件不存在"要么报错、要么少帧静默变短),而日志里一个字都没有。现在只有真的搬成功才推进帧号(序列始终连续),失败前多给两次机会,失败一定写日志(逐帧 WARN + 段末 ERROR 汇总,并说明本段少了几帧)。
  • "视频不落 CPU"这条策略的最后一处口子 —— 堵上了:旧版报错会建议你"到设置 → 计算设备里选「CPU 计算」",但那个选项早就不在设置里(下拉只列显卡),照做只会白找;更麻烦的是代码把"设备编号 < 0"当成了"用户选了 CPU",而 Vulkan 自检失败时软件会临时把编号置 -1 ⇒ 这种机器上的视频会静默走 CPU 软编 —— 正是这条策略要消灭的东西。现在视频一律要求可用硬件编码器,没有就开跑前直接报错并给出可执行的自救(更新 / 重装驱动、重启、确认显卡没被禁用)。 不受影响:图片放大 / 抠图 / 音频处理没有显卡时照样用 CPU 跑完。
  • 清掉一批"死东西" + 更新检查不再刷屏:三处永远看不到的界面(图片页那条常驻隐藏的橙色倍率提示、视频页那条没有名字所以代码引用不到的裁剪提示、左右对比那条早已不再出现的"待生效位置"虚影线)与四处零调用点的死代码(硬链接工具、freezedetect 抽静止段、scene 抽转场段、RIFE 的位图重载 + 解码入口)全删;本机 GitHub 接口稳定 403 / 超时时一次启动会刷 6 条几乎一样的日志 ⇒ 现在同一通道只详细报一次,末尾给一句汇总;音频列表处理完的文字("文件名 (已处理)")以前不会出现在界面上,现在会刷新。
  • 这一版「故意没做」的一件事(说明白):核查报告里的「分段编码自动触发」没做 —— 分段编码目前只作用于编码阶段,而峰值磁盘占用发生在更早的"逐帧处理"阶段,中途自动开分段只会让"本来要失败的任务"多跑一段再失败。维持现有口径:开跑前按实际峰值算够不够,不够就拦下并给量化建议,不假装能自动兜住。(流水线方案见仓库 docs/。)
  • 视频抠图 —— 整条删除(用户定案"以后不会再做了"):那一页 2026-09-22 建好后一直锁着"开发中 · 敬请期待"、从未开放过;它的成本与收益不匹配:1080p 逐帧(ONNX 推理 + 蒙版后处理 + 时域稳定 + 合帧编码)实测约 0.35 秒/帧 ⇒ 60 秒的片子约 10.5 分钟,而"换背景 / 出透明通道"在剪辑软件里是常规操作。 按用户要求"留一点有用的"保留下来的两样:① AlhPro.Core 里那批纯逻辑工具件(蒙版后处理阈值 / 羽化 / 形态学、换背景合成、镜头切点判定 + 时域稳定滤波,都带单测,将来做图片抠图的边缘质量或任何逐帧蒙版能直接拿来用 —— 实测 1080p 后处理默认档 82 ms/帧、时域滤波 3.9 ms/帧、合成 10.3 ms/帧);② 一份新文档 docs/2026-09-23-视频抠图下线-保留的经验与可复用件.md(四个抠图模型的 GPU / CPU 速度与"软边占比"、"只出蒙版 vs 完整路径"相差 120~134 ms/帧、透明视频编码的两个坑 —— 都是花钱测出来的)。 老设置兼容:启动页若存过"视频抠图"会被判为非法 ⇒ 自动回落到"上次退出界面"。左侧导航现在剩 4 个功能页(图片放大 / 图片抠图 / 视频处理 / 音频处理)。
  • 视频 2x 超分被静默推到"慢 13 倍"的路 —— 已修(实测同一段素材快 28 倍):同一台机器、同一段 3 秒 720p 素材,「2x 超分」实测 3880 毫秒/帧(90 帧要跑约 6 分钟),而软件自己给这支模型标的是 0.26~0.30 秒/帧。根因是一串很隐蔽的连锁:视频页「动漫 · Anime4K 修复(快)」的内部标识 anime4k 实际走 ffmpeg 着色器、根本不用 ncnn 引擎,但开跑前的"显卡兼容性预检"会把当前选中的那一项原样当模型名交给 ncnn 去加载 ⇒ ncnn 被要求加载不存在的模型 ⇒ 探 60 秒没响应被强杀 ⇒ 落一条假的"realesrgan 在本机不可用"结论;而"独显 + 核显"的机器每次预检都带模型名、从不写"引擎级"结论 ⇒ 那条假失败就成了整条 Real-ESRGAN 引擎的判据 ⇒ 之后所有 2x/3x/4x 视频超分都改走 ONNX 慢路。 修法:① 预检前把"伪模型"回落成"探引擎默认模型",不再落假结论;② 兜底的引擎判定只统计真 ncnn 模型的结论(已落盘的旧假结论也因此被忽略,不用你自己删文件)。实测(修后、同一段素材同一台机器):路线回到 ncnn-Vulkan、136 毫秒/帧,整个任务 22.3 秒(修前同配置约 6 分钟)⇒ 单帧快 28 倍。
  • 显卡探测:一次"60 秒无响应"不再把整台机器判成慢路:只有"无响应 / 超时"这种瞬时形态会先退避 3 秒重试一次,仍失败才落盘;确定性失败(初始化即崩、参数错误、出图但坏帧)一次都不重试;日志如实写"第几次失败 → 退避后重试 → 结果"。 同时修掉两条独立审查抓到的:① 用户在探测卡住时点「取消」,以前会落一条 1 天的失败结论(等于因为一次取消、当天全走慢路)且日志错误归因成"确定性失败" —— 现在取消一律不落任何结论;② 日志里"重试第 2/1 次"这种自相矛盾的措辞已修。 顺手把一处旧保险保了回来:挑卡路径对确定性失败的重试按调用点分档恢复(全帧生产探测 = 仅超时重试一次;小图活性检查 = 确定性失败 1.5 秒 × 最多 3 次)。
  • 音频那条"白试"再往前走一步:跨天也记得住(并随驱动变化自动作废):失败结论原先只记 1 天 —— 对"一天只跑一次"的用户等于没记住(下次开软件刚好过期),仍会每次会话白试一次。现在失败结论与成功一样记 7 天(第 1、2、3 次会话累计到上限后,第 4 次起就不再白试);"换了驱动 / 换了显卡该怎么办"改由环境签名负责:账本里记一行"显卡名@驱动版本",读回时若与本机现在的不一致(装 / 换驱动、换卡、插拔 eGPU)⇒ 整份结论作废、重新试一次。 诚实边界:这不是"白试已消除" —— 稀疏用户在前几次会话仍会各白试一次;而"建会话当场失败"那条结构性路径仍是一次判死、即刻生效。
  • 启动自检的"所有候选卡都卡死"最坏耗时砍掉三分之一:挑卡档对"卡死"原本也重试 3 次,而这一档要在多张候选卡上逐个试、每次卡死都要等满 15 秒超时 ⇒ 独立审查算过:全部候选都卡死时启动自检最坏约 4.8 分钟。现在"卡死"在这档单独限 2 次(仍保留一次重试覆盖"驱动 / 显存刚开始回收"的瞬时状态),最坏降到约 3.2 分钟;"进程崩一下"这类确定性失败仍是 3 次保险不变。边界:这是算式(6 张候选卡 × 单卡最坏耗时),不是实测。
  • AMD / Intel 机器现在也能真读空闲显存了(不再是"未实测"):此前"当前空闲显存"只有 NVIDIA 能真读(nvidia-smi),A 卡与核显上一律报"未实测" ⇒ 显存墙与并发档位在那些机器上整层失效。现在补了第二条跨厂商路径:用 Windows 自带的性能计数器「GPU Adapter Memory」读"已用",再与 DXGI 报的显存总量相减得空闲(换算与实例名解析都在 Core、有单测);日志与诊断包里会写明这个数字是谁给的(6.3 GB(nvidia-smi) / 6.5 GB(PDH(GPU Adapter Memory)))。 边界(如实):多卡机拿不到目标卡 LUID 时按全部实例求和 ⇒ 偏保守(宁可少放批次);两者都读不到时仍照旧报"未实测",绝不返回估值冒充实测。(AMD / Intel 的温度读数本版没做:Intel 侧没有公开接口、AMD 需 ADL 且本机无 A 卡,不发没验过的。)

v1.4.0 2026-09-16 · 新增超分模型与两支测试模型 + 视频「边缘增强」+ 下拉重排 + 超分提速与黑帧降级修复

新增自研转换的超分模型、两支标着「测试」的自训 2x 模型、视频「边缘增强」后处理,超分模型下拉重排(老设置自动迁移);修复「指定帧率」下临时空间被算少一半的问题,并集中修掉一批"不报错、只是慢或悄悄做错"的问题 —— 8GB 显卡超分提速约 1.6 倍、超分遇到黑帧不再整批重跑几十分钟
  • 新增超分模型 realesr-general-wdn-x4v3(自研转换): 权重取自上游 Real-ESRGAN 官方 release v0.2.5.0(BSD 3-Clause),本项目自行转成 ncnn 与 ONNX 格式。 1080p 约 0.46 秒/帧,游戏、动漫素材上的细节优于原来的默认模型。
  • 新增两支自训 2x 模型「现实 · real2x / 游戏 · game2x」(下拉里带一个蓝色「测试」小标): 定位是先把颜色调准 —— 实测色偏(越小越准)三档都低于官方默认模型:游戏帧 0.18 / 0.34(官方 2.00)、动漫帧 0.04 / 0.18(官方 2.73)、实拍 2.53 / 1.48(官方 6.34); 代价是纹理量(detail)多数低于官方默认模型(游戏帧 2.36 / 3.20 对 2.91、动漫帧 1.55 / 1.83 对 2.06、实拍 59.97 / 59.13 对 73.66 —— 只有游戏帧上「现实 · real2x」的 3.20 略高于官方 2.91)。所以这两个位置只给实测数字,不写“更强 / 推荐”。
  • ⚠ 关于这两支的两条边界:
    • 通道验收已通过:引擎输出与源逐通道均值差 小于 0.4 级(判据 小于 5)⇒ 颜色与源一致,可直接用于正片。
    • 只有 2x 原生权重:选 3x / 4x 时仍按原生 2x 跑一遍、再把成片缩放到目标尺寸;推荐用 2x。
    • 没有 ONNX 权重:走「稳定引擎(ONNX)」的机器(50 系 / 兼容模式)用不到它们,软件会明确说明本批按另一支官方模型处理,不会闷声换模型。
  • 视频页「超分模型」下拉按速度与体积重排: 顺序变了,但你以前保存的模型选择会自动对应到新顺序上的同一个模型,不用重选。
  • 界面标签统一简写,修掉部分下拉文字被裁切:以前把模型名 + 体积 + 耗时塞在一行,窗口窄了会截断。
  • 视频新增「边缘增强」后处理:只加强明确边缘,用阈值把平坦区与噪点保护起来。 实测游戏素材:强边缘对比度 +11%,过冲仅上升 0.35 个百分点。 默认值随所选超分模型给(animevideov3 = 30,其它模型 = 60)。
  • 修复「指定帧率」下临时空间被算少一半(长视频会跑到一半爆盘、后段满是灰帧): 用「指定帧率」时,软件会按目标帧率把补帧倍率自动抬高(比如你选 2x,它抬到 4x), 但“要占多少临时空间”这笔账以前是在开工前按你选的 2x 算的 —— 倍率翻一倍、要占的地方也翻一倍,于是空间被算少近一半: 检查以为够就放行,跑到一半临时盘满,后半段中间帧写成残帧,只能拿深灰占位帧顶上(帧号连续、内容是废的)。 现在改成倍率定稿后按最终倍率把账重算一遍、再判一次空间,不够就在开跑前拦下并告诉你需要多少 GB。 只改“拦人时怎么算账”,画质与处理结果不受影响。
  • 8GB 显卡的超分提速约 1.6 倍: 以前 8GB 显存会被判成“只够单路”,根因是个 3 MB 的换算零头 —— 8GB 卡实际报 8188 MiB, 换算成 7.996 GB 再 ×0.75 = 5.997,与门槛 6.0 只差 0.003,于是整张卡掉回单路。 现在恢复两路并行:同一批素材实测 单路 3.66 帧/秒 → 两路 5.97 帧/秒(1.63 倍),输出逐帧检查无黑帧。 (6GB 卡仍是单路,不受影响;想看自己机器跑了几路,可看日志里的「并发路数」。)
  • 超分遇到黑帧不再“整批重跑”: 以前某个批次里只要有一帧被判黑,就把整批作废、换引擎重跑整批 —— 真机上这一跑能到二十多分钟, 而且重跑仍黑时整批退回未超分的源帧(那一段画质整体掉档)。 现在只重跑被判黑的那几帧(同批好帧保留),并给重跑加硬预算(最长几分钟), 到点就停、只把没救回来的帧退回源帧;零星 1 帧黑也不会再让后面的批次全部改用慢引擎。
  • 修掉「指定帧率」链路上的三处静默错误:
    • 切点判据只算一次、两条路共用(以前“普通分段”与“按真实时间戳排帧”各算一次 = 同一份判据两次全片解码, 而且其中一条路无视「转场识别」开关 —— 你明明没勾,它照样做切点保护);
    • 「按真实时间戳排帧」只在源确实是可变帧率(VFR)时生效,固定帧率的素材走常规处理;
    • 「去重」+「指定帧率」同时开时不再丢掉原片节奏(以前输出帧会按目标帧率均匀铺开: 该停的地方被快进、该快的地方被拉慢,总时长不变,但你会觉得“内容好像丢了”)。
  • 指定帧率导出的文件名直接写帧率: 以前是「…_补帧2x(自动3x)_rife413_60fps.mp4」这种重复三段的样子,现在就是「…_补帧60fps_rife413.mp4」。
  • 音频页的「强制结束」改成红色:与视频 / 抠图 / 图片页一致 —— 以前只有它是灰的,看着不像能停任务的按钮。
  • 诊断日志补强(只写日志文件,不往界面刷): 超分阶段每批记录「引擎 ms/帧 + 落盘 ms/帧 + 实际引擎参数 + 并发路数」,阶段末尾记录 GPU 利用率区间 —— 以后“怎么变慢了”看这两行就能定性:利用率长期只有六七成 ⇒ GPU 没吃饱;95%+ ⇒ 就是 GPU 算力这一层。
  • 修官网「AI 抠图」演示图被容器裁切的问题:现在完整显示。

v1.3.5 是在 v1.3.4 那批修复的基础上又打的一次包,v1.3.4 的内容也已包含在内。机器可读的版本记录见公开仓库的 release_history.json。

v1.3.3 2026-09-08 · 稳定性 / 兼容性 / 速度增强

修复一批隐性缺陷,并提升视频处理速度
  • 探测看门狗(治“处理卡死只能强杀”):开始处理前会用 ffmpeg 完整扫一遍视频,这一步以前没有超时保护。 现在启动静默 90 秒 / 运行静默 120 秒会自动掐掉并提示。
  • 修 x4plus 系超分输出全黑帧:个别卡(尤其 RTX 50 系新驱动)会静默输出全黑帧,根源是引擎线程档位过高,现封顶 6。
  • 回退帧统一缩放,治花屏:超分失败回退原帧时先统一尺寸再写入,避免混入异尺寸帧导致成片花屏。
  • 硬编探测修复:以前只编 1 帧就被判“无效”而静默禁用;现在会多编几帧。
  • 视频超分提速(相同帧只超分一次):内容完全一样的帧按哈希去重,只算一次、其余复用结果 —— 无损提速。
  • 预计时间更准(四个阶段都有 ETA):每阶段用各自的净耗时时钟。
  • GPU 识别修正(治“有独显却走 CPU”):修复注册表枚举与引擎枚举编号错位的问题。
  • 不轻易掉 CPU,掉的时候明确提示:GPU 可用性探测改为 3 次重试 + 更宽松的超时;真降级会提示“速度会变得特别慢”。
  • 排查手段加强:超分 / 编码实际走的设备全部记进诊断包。
  • 赞赏提示更克制(冷却 10 小时)。

v1.3.2 2026-09-07 · 视频稳定性加固 + 补帧降级链 + 设备识别修复

重点修复黑帧、黑屏、补帧残缺与显卡误判
  • 兼容模式对 NVIDIA 卡也走 ONNX:避开 ncnn-Vulkan 偶发黑帧;检测到黑帧后后续批次直接改用 ONNX。
  • 编码器不再优先用不可靠的 QSV:仅在无其它可用硬编时兜底;探测分辨率从 320×240 提到 1280×720。
  • 补帧降级链:失败 / 黑帧 / 0 帧时按「显卡 → ONNX(DirectML)→ 换卡」降级,不会静默掉到慢速 CPU。
  • 修复独显被误判成 CPU:显卡编号稀疏时会被当成无效设备,现已按引擎设备表判断。
  • Real-ESRGAN 探测超时放宽 5 秒 → 15 秒,并显示“正在检测显卡兼容性”,冷启动慢的卡不再被误判成卡死。
  • 视频帧转 JPG 直接走 GDI,更快更可靠。
  • 参数记忆修复:码率 / 格式 / 编码等下拉的“记住上次”恢复生效;补帧倍率 12x / 16x 也能被记住。
  • 新版本提示改回顶部横幅(不弹窗打断),点 ✕ 本次不再显示。

v1.3.1 2026-09-06 · 更新弹窗 + 提示 / 广告区强化

版本提示更醒目;界面提示与广告改为随机轮播
  • 检测到新版本 → 延迟 10 分钟弹出升级弹窗(含「去下载 / 网盘下载」),取代原来不醒目的小提示条;被墙会自动换镜像端点并重试。
  • 点「本次不再提示」→ 本次运行不再弹;设置里新增「不再提示更新」开关。
  • 状态栏提示条放宽且常驻;提示与广告改为随机轮播,并避开最近显示过的 4 条。
  • 提示 / 广告数量自适应:仓库新增文件即自动多轮播,无需发版。
  • 广告卡关闭按钮与角标位置优化,不再压住标题。

v1.3.0 2026-09-05 · 自检驱动 + 始终用显卡 + 稳定性

新增启动自检;优先使用显卡;兼容模式与看门狗按设备档次自适应
  • 启动自检(全新):首次启动或版本更新后弹出自检,逐项检测显卡 / 显存 · 驱动 · 内存 · CPU / 引擎 / 各功能模型, 全通过后显示报告,点「确定」进主界面。
  • 始终用显卡:通用引擎的降级链去掉“GPU → CPU”;计算设备下拉移除 CPU 选项,默认取自检实测的最佳独显。 核显只作兜底。
  • 大显存机型吃满显卡:ONNX 超分分块自适应(512 → 768)+ 3 路并行。
  • 兼容模式加强:自动降低分块与批大小防止爆显存,对风险显卡强制走 ONNX 稳定路线。
  • 黄字提醒更全:黑帧降级、显存不足降分块、高倍率补帧、走 ONNX、临时盘紧张等都会提示。
  • 源兼容:HDR / 广色域源自动转 BT.709 SDR;超大图加入尺寸与内存保护;MKV 无损音轨不再被强制转 AAC; 分辨率超 4K 或帧率超 240 会给出提示。

v1.0.0 首个正式版

图片超分、AI 抠图、视频超分 / 补帧 / 去重的首个完整版本

从早期的 v0.3 / v0.5 预览版迭代而来:v1.0 起把「图片放大、AI 抠图、视频处理」整合到统一界面, 后续版本又加入了批量管理、去重复帧、音频处理与设备自检。各版本软件包见公开仓库的发布页。

已知限制

  • 音频 AI 分离优先用显卡(DirectML);无显卡或驱动不兼容时用 CPU,约 1.5 分钟 / 分钟音频。
  • 音频「升采样率」只对低采样率源(8k / 16k / 22k / 32k)有效;44.1 kHz 音乐已是全频带,改用「增强」。
  • 视频超分 / 补帧在老电脑上慢是物理限制,建议从 waifu2x 与 1x~2x 倍率起步。
  • AI 抠图固定用 CPU(避免占满显卡导致整机卡顿),图片多时要耐心等。
